## 套路卡（先读「一句话版」，懂了就往下跳到做题）

> ### 一句话版
> 遇到「某东西**出现过没有 / 出现过几次 / 和谁能配上对**」时，
> 不要一遍遍去数（太慢），而是**边看边记在小本本上**；
> 之后一翻本子就知道答案。这个小本本就叫**哈希表（hash table）**。

### 0. 先别管名字，看个生活场景

老师给你一串数字，问：**里面有没有重复的？**

| 笨办法（慢） | 聪明办法（快） |
|---|---|
| 拿第 1 个数，去后面一个一个比；再拿第 2 个…… | 拿一张纸，从左往右看，每个数先「查纸上有没有」： |
| 数越多越慢（n 个数要比约 n² 次） | 没有 → 写上去；有 → 立刻说「有重复！」 |
| 每个数都要**跟很多数比** | 每个数只看一次，**查纸几乎瞬间** |

这张纸 = **哈希表**。「查纸」这个动作叫**查表**，平均只要 **O(1)**（常数时间，和数据多少无关）。

```
想记 "apple"：先算它该写在哪一行 ──► 第 3 行，写下它
想查 "apple"：同样算一次 ────────► 直接翻到第 3 行看看有没有
（不用从头一行行找，所以快）
```

### 1. 两个最常用的小本本：`Set` 和 `Map`

| 工具 | 记住什么 | 一句话理解 | 什么时候用 |
|---|---|---|---|
| `Set`（集合） | 只记「有哪些值」 | 一张**不重复的清单** | 判重、判「出现过没有」 |
| `Map`（映射） | 记「值 → 绑定的信息」 | 一本**字典：词 → 解释** | 记次数、记下标等 |

```ts
// ① Set：只关心「有没有」
const seen = new Set<number>();  // 一个装数字的集合
seen.add(3);      // 在本子上记下 3
seen.has(3);      // true  —— 问：记过 3 吗？
seen.has(5);      // false

// ② Map：值 -> 额外信息（这里举例：值 -> 出现次数）
const count = new Map<number, number>(); // <键的类型, 值的类型>
count.set(7, 1);  // 把 7 记成「1 次」
count.set(7, 2);  // 覆盖成「2 次」
count.get(7);     // 2     —— 问：7 对应多少？
count.has(7);     // true  —— 问：记过 7 吗？
```

> **新语法提醒**：`Set<number>`、`Map<number, number>` 里的尖括号叫**泛型**，用来写明「里面装什么类型」。
> 第一次出现的新语法我都会登记到 `notes/typescript-basics.md`（本次新增了 `Map` 的讲解）。

### 2. 什么时候该想到哈希？（认信号）

看到下面这些字眼，就先想想「能不能记个小本本」：

- 「**是否重复 / 有没有出现过**」→ 用 `Set`；
- 「**出现次数 / 频率**」→ 用 `Map` 记次数；
- 「**两数（多数）之和等于某值**」→ 记下「我正在等哪个数」；
- 「**把一堆东西按规则归类**」（比如字母异位词分组）→ 用「归一化后的特征」当键。

### 3. 「O(1) / O(n) / O(n²)」人话解释

| 记号 | 人话 | 例子 |
|---|---|---|
| `O(1)` | 不管多少数据，**步数固定** | 按书号直接抽书 |
| `O(n)` | 数据翻倍，步数大约翻倍 | 从头到尾看一遍 |
| `O(n²)` | 每个元素都跟后面所有元素比一遍 | n=10000 时要约 1 亿次，很慢 |

**哈希的价值**：把「一个个去找」的 `O(n)` 查找，换成「翻小本本」的 `O(1)`。

### 4. 常见坑（人话）

- **先查后记**：往本子上写之前先问「有没有」，否则会**自己和自己配对**。
- `Set` 按**值**判重；两个内容相同的**对象**在 `Set` 里算**不同**（按引用比较）。
- 比较用 `===`（三个等号）；`=` 是赋值，`===` 才是「是否相等」。

### 5. 术语表（中英对照）

| 中文 | 英文 | 一句话 |
|---|---|---|
| 哈希表 | hash table | 边看边记的「小本本」 |
| 哈希函数 | hash function | 决定「写在哪一页」的规则 |
| 冲突 | collision | 两个不同的键被算到同一页 |
| 桶 | bucket | 本子里的每一页 / 格子 |
| 键 / 值 | key / value | 查找的线索 / 线索对应的信息 |
| 集合 | Set | 只记「有哪些」的本子 |
| 映射 | Map | 记「键 → 值」的本子 |

## 零基础精讲 ①：看懂 W1 用到的每个零件（先读这段，别急着写代码）

> 这一段把 W1 需要的每个「零件」拆开讲清楚：函数 → 集合 → 循环 → 判断。
> 读完你大概率自己就知道那处 bug 怎么改了。**不用背，跟着例子走一遍即可。**

### 1. 什么是「函数」

```ts
export function hasDuplicate(nums: number[]): boolean {
  // 大括号里写"要做的事"
}
```

- `function` 定义一段「可以被叫去做事」的代码，名字叫 `hasDuplicate`（意思是：判断有没有重复）。
- 括号里的 `nums: number[]` 是**输入**（叫参数）：一个装数字的数组。
- 冒号后的 `boolean` 是**输出**（叫返回值）的类型：只会是「真 `true`」或「假 `false`」。
- `{ }` 里面是「怎么做」。

> 类比：函数像一台**自动售货机**——投进一个数组，吐出一个 `true`/`false`。

### 2. 什么是「集合 Set」（本专题的主角）

想象老师点名：他要判断一个名字**有没有点过**。他在白板上写「已点过的名字」，**重复的不再写**。
这块白板就是 `Set`。

```ts
const seen = new Set<number>();   // 造一块"空白的白板"，只记数字
```

- `const`：给这块白板起个名字叫 `seen`（后面不换人，所以用 `const`）。
- `new Set<number>()`：**新建**一块白板；`<number>` 说明「上面只写数字」，这叫**泛型**（先照抄，后面再细讲）。

它只有两个你最常用的动作：

```ts
seen.add(3);   // 在白板上写下 3
seen.has(3);   // 问：白板上有 3 吗？→ true / false
```

`has` 就是「查白板」，**平均只要 O(1)**（几乎瞬间）——这就是哈希「快」的来源。

### 3. 什么是「循环」，为什么需要它

数组 `[1, 2, 3, 1]` 有好几个元素，你要「**一个个看**」。
这种「把同一件事重复做很多遍」就叫**循环（loop）**。没有循环，你只能手写 4 遍，数组一万个元素就没法办了。

### 4. `for...of`：逐个把「值」拿出来（✅ 你要的）

```ts
for (const x of nums) {
  // 这一对大括号会"对数组里每个元素各做一次"
  // x 就是"当前这个元素"
}
```

假如 `nums = [1, 2, 3, 1]`，执行过程：

| 第几轮 | `x` 的值 |
|---|---|
| 第 1 轮 | `1` |
| 第 2 轮 | `2` |
| 第 3 轮 | `3` |
| 第 4 轮 | `1` |

关键：**`of` 拿的是「值」（元素本身）**。

### 5. `for...in`：拿的是「下标」，而且是字符串（❌ 你踩的坑）

```ts
for (const i in nums) {
  // i 不是元素！i 是"第几个"，而且是字符串 "0" "1" "2" ...
}
```

同样 `nums = [1, 2, 3, 1]`：

| 第几轮 | `i` 的值 |
|---|---|
| 第 1 轮 | `"0"`（字符串，不是数字 0） |
| 第 2 轮 | `"1"` |
| 第 3 轮 | `"2"` |
| 第 4 轮 | `"3"` |

于是 `seen.has("0")` 变成「在一堆**数字**里找**字符串** `"0"`」→ 永远 `false`。

> **一句话记忆**：`for...**of**` 取「**值**」；`for...**in**` 取「**键 / 下标**」。
> 记忆法：**o**f → 元素；**i**n → **i**ndex（下标）。数组取元素，**永远用 `of`**。

### 6. `if / else / return`：做判断、交结果

```ts
if (seen.has(x)) {      // 如果"白板上有 x"
  return true;          // 立刻结束函数，交回 true
} else {                // 否则
  seen.add(x);          // 把 x 记到白板上
}
```

- `if (条件) { ... } else { ... }`：条件为真走 `if`，否则走 `else`。
- `return 值;`：**立刻结束**整个函数，并把结果交回去。

### 7. 把零件拼起来，跟着走一遍（`nums = [1, 2, 3, 1]`）

| 轮次 | `x` | `seen.has(x)`？ | 动作 |
|---|---|---|---|
| 1 | 1 | `false` | `seen.add(1)` → 白板 `{1}` |
| 2 | 2 | `false` | `seen.add(2)` → 白板 `{1,2}` |
| 3 | 3 | `false` | `seen.add(3)` → 白板 `{1,2,3}` |
| 4 | 1 | **`true`** | 命中重复 → `return true`，函数结束 |

如果整个数组走完都没命中，就 `return false`。

### 8. 回头看你自己的代码

你的**思路和第 7 步一模一样**，唯一的问题在第 5 点：用了 `for...in`，拿到的是 `"0"` 而不是元素。
把 `for (var i in nums)` 改成 `for (const x of nums)`（`var` 顺手换成 `const`），就对了。

## 热身 W1：判断数组是否有重复元素（自出 · 简单）

- 文件：`src/01-hash-table/warmup-01-has-duplicate.ts`
- 考点：Set / 哈希去重
- 状态：⚠️ 待修正（见下方批改）

**题目**：给定整数数组 `nums`，若**存在至少一个值出现两次及以上**返回 `true`，否则返回 `false`。

- 示例：`[1,2,3,1] -> true` ｜ `[1,2,3,4] -> false` ｜ `[] -> false`
- 约束：`0 ≤ nums.length ≤ 10^5`
- 进阶（可选，做完再说）：不用额外空间，先排序再比较相邻（时间 O(n log n) / 空间 O(1)）。

**✍️ 我的思路**（先自己写，哪怕一句话）：
>使用Set集合进行判断 先检查数字有没有在集合中 如果没有则登记 如果有则返回true 遍历结束后返回false

**✍️ 我的代码（TypeScript）**：

> （Agent 按 R8 整理，仅调整缩进，未改结论）

```ts
export function hasDuplicate(nums: number[]): boolean {
  const num = new Set<number>();
  for (var i in nums) {
    if (num.has(i)) {
      return true;
    } else {
      num.add(i);
    }
  }
  return false;
}
```

**复杂度自评**：（未填）

**✅ 批改（2026-09-27）**：

**判定**：⚠️ **思路完全正确，但实现有 1 处硬伤 → 当前不 AC**。
（`vitest`：5 个测试 **2 failed / 3 passed**；`tsc --noEmit`：**2 个类型错误**。）

**为什么错**：
- `for (var i in nums)` 用的是 **`for...in`**，它遍历的是**键 / 下标**，而且下标是**字符串** `"0"`、`"1"`…
  —— 你拿到的**不是数组里的值**。
- 你的 `num` 是 `Set<number>`（只装数字），却用字符串下标去 `has` / `add`：
  - `num.has("0")` 永远 `false`（`"0"` ≠ `0`）→ 所以函数**恒返回 false**。
  - tsc 直接报错（第 12、15 行）：`Argument of type 'string' is not assignable to parameter of type 'number'`。
- 次要：`var` 是老写法（作用域易错），本项目统一 `const` / `let`。
- 证据：期望 `true` 的 2 个用例挂了；期望 `false` 的 3 个用例「碰巧」过了（因为恒为 false）。

**改法（最小修改）**：把「取值方式」从 `for...in` 换成 **`for...of`**：
- `for (var i in nums)` → `for (const x of nums)`
- 并建议把集合改名为 `seen`、元素叫 `x`，避免混淆。
- 原理详见 `notes/typescript-basics.md` 的 **011. `for...in` vs `for...of`**，以及本专题上方的 **《零基础精讲 ①》第 4、5 节**。

**复杂度复核**：正确为 **时间 O(n)**（每个元素查一次 Set，平均 O(1)），**空间 O(n)**（最坏存下全部元素）。你的自评是空的，下次记得写。

**同类变式题（改完后做）**：返回**第一个重复出现的数字**（没有则返回 `-1`）。
- L1 提示：命中 `seen.has(x)` 时 `return x`，否则 `seen.add(x)`。

**复盘**：
- 卡点：`for...in` 取的是下标（字符串），不是值；`Set<number>` 与字符串比较永不相等。
- 一句话套路：**`for...of` 取值，`for...in` 取键**；写完先跑 `npx tsc --noEmit`，类型错误会提前抓住这类 bug。
