## 套路卡（先读「一句话版」，懂了就往下跳到做题）

> ### 一句话版
> 遇到「某东西**出现过没有 / 出现过几次 / 和谁能配上对**」时，
> 不要一遍遍去数（太慢），而是**边看边记在小本本上**；
> 之后一翻本子就知道答案。这个小本本就叫**哈希表（hash table）**。

### 0. 先别管名字，看个生活场景

老师给你一串数字，问：**里面有没有重复的？**

| 笨办法（慢） | 聪明办法（快） |
|---|---|
| 拿第 1 个数，去后面一个一个比；再拿第 2 个…… | 拿一张纸，从左往右看，每个数先「查纸上有没有」： |
| 数越多越慢（n 个数要比约 n² 次） | 没有 → 写上去；有 → 立刻说「有重复！」 |
| 每个数都要**跟很多数比** | 每个数只看一次，**查纸几乎瞬间** |

这张纸 = **哈希表**。「查纸」这个动作叫**查表**，平均只要 **O(1)**（常数时间，和数据多少无关）。

```
想记 "apple"：先算它该写在哪一行 ──► 第 3 行，写下它
想查 "apple"：同样算一次 ────────► 直接翻到第 3 行看看有没有
（不用从头一行行找，所以快）
```

### 1. 两个最常用的小本本：`Set` 和 `Map`

| 工具 | 记住什么 | 一句话理解 | 什么时候用 |
|---|---|---|---|
| `Set`（集合） | 只记「有哪些值」 | 一张**不重复的清单** | 判重、判「出现过没有」 |
| `Map`（映射） | 记「值 → 绑定的信息」 | 一本**字典：词 → 解释** | 记次数、记下标等 |

```ts
// ① Set：只关心「有没有」
const seen = new Set<number>();  // 一个装数字的集合
seen.add(3);      // 在本子上记下 3
seen.has(3);      // true  —— 问：记过 3 吗？
seen.has(5);      // false

// ② Map：值 -> 额外信息（这里举例：值 -> 出现次数）
const count = new Map<number, number>(); // <键的类型, 值的类型>
count.set(7, 1);  // 把 7 记成「1 次」
count.set(7, 2);  // 覆盖成「2 次」
count.get(7);     // 2     —— 问：7 对应多少？
count.has(7);     // true  —— 问：记过 7 吗？
```

> **新语法提醒**：`Set<number>`、`Map<number, number>` 里的尖括号叫**泛型**，用来写明「里面装什么类型」。
> 第一次出现的新语法我都会登记到 `notes/typescript-basics.md`（本次新增了 `Map` 的讲解）。

### 2. 什么时候该想到哈希？（认信号）

看到下面这些字眼，就先想想「能不能记个小本本」：

- 「**是否重复 / 有没有出现过**」→ 用 `Set`；
- 「**出现次数 / 频率**」→ 用 `Map` 记次数；
- 「**两数（多数）之和等于某值**」→ 记下「我正在等哪个数」；
- 「**把一堆东西按规则归类**」（比如字母异位词分组）→ 用「归一化后的特征」当键。

### 3. 「O(1) / O(n) / O(n²)」人话解释

| 记号 | 人话 | 例子 |
|---|---|---|
| `O(1)` | 不管多少数据，**步数固定** | 按书号直接抽书 |
| `O(n)` | 数据翻倍，步数大约翻倍 | 从头到尾看一遍 |
| `O(n²)` | 每个元素都跟后面所有元素比一遍 | n=10000 时要约 1 亿次，很慢 |

**哈希的价值**：把「一个个去找」的 `O(n)` 查找，换成「翻小本本」的 `O(1)`。

### 4. 常见坑（人话）

- **先查后记**：往本子上写之前先问「有没有」，否则会**自己和自己配对**。
- `Set` 按**值**判重；两个内容相同的**对象**在 `Set` 里算**不同**（按引用比较）。
- 比较用 `===`（三个等号）；`=` 是赋值，`===` 才是「是否相等」。

### 5. 术语表（中英对照）

| 中文 | 英文 | 一句话 |
|---|---|---|
| 哈希表 | hash table | 边看边记的「小本本」 |
| 哈希函数 | hash function | 决定「写在哪一页」的规则 |
| 冲突 | collision | 两个不同的键被算到同一页 |
| 桶 | bucket | 本子里的每一页 / 格子 |
| 键 / 值 | key / value | 查找的线索 / 线索对应的信息 |
| 集合 | Set | 只记「有哪些」的本子 |
| 映射 | Map | 记「键 → 值」的本子 |

## 零基础精讲 ①：看懂 W1 用到的每个零件（先读这段，别急着写代码）

> 这一段把 W1 需要的每个「零件」拆开讲清楚：函数 → 集合 → 循环 → 判断。
> 读完你大概率自己就知道那处 bug 怎么改了。**不用背，跟着例子走一遍即可。**

### 1. 什么是「函数」

```ts
export function hasDuplicate(nums: number[]): boolean {
  // 大括号里写"要做的事"
}
```

- `function` 定义一段「可以被叫去做事」的代码，名字叫 `hasDuplicate`（意思是：判断有没有重复）。
- 括号里的 `nums: number[]` 是**输入**（叫参数）：一个装数字的数组。
- 冒号后的 `boolean` 是**输出**（叫返回值）的类型：只会是「真 `true`」或「假 `false`」。
- `{ }` 里面是「怎么做」。

> 类比：函数像一台**自动售货机**——投进一个数组，吐出一个 `true`/`false`。

### 2. 什么是「集合 Set」（本专题的主角）

想象老师点名：他要判断一个名字**有没有点过**。他在白板上写「已点过的名字」，**重复的不再写**。
这块白板就是 `Set`。

```ts
const seen = new Set<number>();   // 造一块"空白的白板"，只记数字
```

- `const`：给这块白板起个名字叫 `seen`（后面不换人，所以用 `const`）。
- `new Set<number>()`：**新建**一块白板；`<number>` 说明「上面只写数字」，这叫**泛型**（先照抄，后面再细讲）。

它只有两个你最常用的动作：

```ts
seen.add(3);   // 在白板上写下 3
seen.has(3);   // 问：白板上有 3 吗？→ true / false
```

`has` 就是「查白板」，**平均只要 O(1)**（几乎瞬间）——这就是哈希「快」的来源。

### 3. 什么是「循环」，为什么需要它

数组 `[1, 2, 3, 1]` 有好几个元素，你要「**一个个看**」。
这种「把同一件事重复做很多遍」就叫**循环（loop）**。没有循环，你只能手写 4 遍，数组一万个元素就没法办了。

### 4. `for...of`：逐个把「值」拿出来（✅ 你要的）

```ts
for (const x of nums) {
  // 这一对大括号会"对数组里每个元素各做一次"
  // x 就是"当前这个元素"
}
```

假如 `nums = [1, 2, 3, 1]`，执行过程：

| 第几轮 | `x` 的值 |
|---|---|
| 第 1 轮 | `1` |
| 第 2 轮 | `2` |
| 第 3 轮 | `3` |
| 第 4 轮 | `1` |

关键：**`of` 拿的是「值」（元素本身）**。

### 5. `for...in`：拿的是「下标」，而且是字符串（❌ 你踩的坑）

```ts
for (const i in nums) {
  // i 不是元素！i 是"第几个"，而且是字符串 "0" "1" "2" ...
}
```

同样 `nums = [1, 2, 3, 1]`：

| 第几轮 | `i` 的值 |
|---|---|
| 第 1 轮 | `"0"`（字符串，不是数字 0） |
| 第 2 轮 | `"1"` |
| 第 3 轮 | `"2"` |
| 第 4 轮 | `"3"` |

于是 `seen.has("0")` 变成「在一堆**数字**里找**字符串** `"0"`」→ 永远 `false`。

> **一句话记忆**：`for...**of**` 取「**值**」；`for...**in**` 取「**键 / 下标**」。
> 记忆法：**o**f → 元素；**i**n → **i**ndex（下标）。数组取元素，**永远用 `of`**。

### 6. `if / else / return`：做判断、交结果

```ts
if (seen.has(x)) {      // 如果"白板上有 x"
  return true;          // 立刻结束函数，交回 true
} else {                // 否则
  seen.add(x);          // 把 x 记到白板上
}
```

- `if (条件) { ... } else { ... }`：条件为真走 `if`，否则走 `else`。
- `return 值;`：**立刻结束**整个函数，并把结果交回去。

### 7. 把零件拼起来，跟着走一遍（`nums = [1, 2, 3, 1]`）

| 轮次 | `x` | `seen.has(x)`？ | 动作 |
|---|---|---|---|
| 1 | 1 | `false` | `seen.add(1)` → 白板 `{1}` |
| 2 | 2 | `false` | `seen.add(2)` → 白板 `{1,2}` |
| 3 | 3 | `false` | `seen.add(3)` → 白板 `{1,2,3}` |
| 4 | 1 | **`true`** | 命中重复 → `return true`，函数结束 |

如果整个数组走完都没命中，就 `return false`。

### 8. 回头看你自己的代码

你的**思路和第 7 步一模一样**，唯一的问题在第 5 点：用了 `for...in`，拿到的是 `"0"` 而不是元素。
把 `for (var i in nums)` 改成 `for (const x of nums)`（`var` 顺手换成 `const`），就对了。

**📘 C++ 对照（TS 通过后阅读）**：

```cpp
// cpp/01-hash-table/warmup-01-has-duplicate.cpp
#include <vector>
#include <unordered_set>

bool hasDuplicate(const std::vector<int>& nums) {
    std::unordered_set<int> seen;     // ≈ TS 的 new Set<number>()
    for (int x : nums) {              // 范围 for ≈ TS 的 for (const x of nums)
        if (seen.count(x) > 0) {      // count > 0 即"存在" ≈ seen.has(x)
            return true;
        }
        seen.insert(x);               // ≈ seen.add(x)
    }
    return false;
}
```

- **TS ↔ C++ 关键差异**：

  | 目的 | TypeScript | C++ |
  |---|---|---|
  | 动态数组 | `number[]` | `std::vector<int>` |
  | 哈希集合 | `Set<number>` | `std::unordered_set<int>` |
  | 判存在 | `seen.has(x)` | `seen.count(x) > 0` |
  | 加入 | `seen.add(x)` | `seen.insert(x)` |
  | 遍历值 | `for (const x of nums)` | `for (int x : nums)` |
  | 传参 | 直接传数组 | `const std::vector<int>&`（引用且只读，避免复制） |

## 零基础精讲 ②：从「有没有」到「有几次」——认识 `Map`（W2 配套）

> W1 你已经会用 `Set` 了（它只记「有没有」）。W2 要升级：不仅要记「出现过」，
> 还要记「**出现了几次**」。这时候需要 `Map`。

### 1. 为什么 `Set` 不够用

`Set` 只会告诉你「3 在不在册」，**不记得 3 出现过 2 次还是 5 次**。
要记「一个值 → 它对应的信息（次数）」，就要用 **`Map`（映射 / 字典）**。

> 类比：`Set` 是**点名册**（只记到没到）；`Map` 是**字典**（每个词后面还跟着解释）。

### 2. `Map` 长什么样

```ts
const count = new Map<number, number>();  // <键的类型, 值的类型>
```

- 尖括号里是**两个**类型，用逗号隔开：**前面是「键」的类型，后面是「值」的类型**。
- `Map<number, number>` 读作「数字 → 数字」（值 → 次数）。
- 这仍叫**泛型**：先照抄，用多了自然懂。

### 3. 三个最常用动作

```ts
count.set(7, 1);   // 写下：7 → 1（没有就新增，已有就覆盖）
count.get(7);      // 取出 7 对应的值 → 1
count.has(7);      // 问：记过 7 吗 → true / false
```

- `set(键, 值)`：写 / 改。
- `get(键)`：读；**如果这个键没记过，返回 `undefined`**（不是报错）。
- `has(键)`：判断记过没有。

### 4. 「次数 +1」怎么写？（重点）

想做到「之前记过就 +1，没记过就从 1 开始」，要**先读、再写**：

```ts
// 1) 读当前次数；没记过时 get 返回 undefined，用 ?? 兜底成 0
const old = count.get(x) ?? 0;
// 2) 在原次数上加 1，再写回去
count.set(x, old + 1);
```

**新语法 `??`（空值合并）：**
- `a ?? b` 的意思：**a 不是 `null` 也不是 `undefined` 就用 a，否则用 b**。
- 这里 `count.get(x) ?? 0`：取到次数就用次数；取不到（`undefined`）就当作 `0`。
- 和 `||` 的区别（以后细讲）：`??` 只对 `null/undefined` 兜底，所以 `0`、`""` 会被正常保留。

> 更紧凑的等价写法（一行）：`count.set(x, (count.get(x) ?? 0) + 1);` —— 先理解拆开的两行，再看这一行。

### 5. 跟着走一遍（`nums = [1, 1, 2]`）

| 轮次 | `x` | 当前 count | 动作 |
|---|---|---|---|
| 1 | 1 | `{}` | `get(1)` → `undefined` → `??0` = 0 → `set(1, 1)` |
| 2 | 1 | `{1→1}` | `get(1)` → 1 → `set(1, 2)` |
| 3 | 2 | `{1→2}` | `get(2)` → `undefined` → 0 → `set(2, 1)` |

最后得到 `{1→2, 2→1}`（1 出现 2 次，2 出现 1 次）。

### 6. 你要做的

用 `for...of` 遍历 `nums`，对每个 `x`，用上面的 `get ?? 0` + `set` 维护次数，最后 `return count;`。

## 零基础精讲 ③：两数之和的「补数」思想（真题 1 配套）

> 目标：**先不写代码**，把这个套路想通。想通了，代码其实很短。

### 1. 题目在问什么

数组 `nums`、目标值 `target`，找**两个**数，使它们相加等于 `target`，返回它们的**下标**。

例：`nums = [2,7,11,15], target = 9` → 因为 `2 + 7 = 9`，返回 `[0,1]`。

### 2. 笨办法（先想得到，只是慢）

枚举所有「两两组合」：第 1 个数配后面每个，第 2 个数再配后面每个……
n 个数要试约 n² 次 → 慢。**先知道它能做，再想怎么优化。**

### 3. 聪明办法的核心：盯住「当前数」，算出「我在等谁」

从左往右看，拿起一个数 `x`。我想找一个 `y`，让 `x + y = target`。
那 `y` 必须等于 **`target - x`**。这个 `y` 就叫 `x` 的**补数（complement）**。

- 问题就从「找两个数」变成了：**「我需要的那个数，我之前见过吗？」**
- 这正是哈希的拿手好戏 —— 用**小本本**（这里用 `Map`）。

### 4. 小本本里记什么？

因为最后要**返回下标**，所以本子记「**数 → 下标**」，也就是 `Map<number, number>`。

- 记：见过 `x`，就写下 `x → x 的下标`；
- 查：看 `target - x` 在不在本子里。

### 5. 关键顺序：先「查」，后「存」

对当前 `x`：

1. **先查**：本子里有 `target - x` 吗？
   - 有 → 它的下标 + 当前下标，就是答案，**直接返回**；
   - 没有 → 进入第 2 步。
2. **后存**：把 `x → 当前下标` 记进本子，再看下一个数。

> 为什么必须「先查后存」？如果先把 `x` 存进去、再查 `target - x`，
> 当补数正好等于 `x` 自己时（例如 `target = 4, x = 2`），会**查到自己**、自己和自己配对，就错了。

### 6. 跟着走一遍（`nums = [2,7,11,15], target = 9`）

| 下标 | `x` | 补数 `9 - x` | 本子里有吗？ | 动作 |
|---|---|---|---|---|
| 0 | 2 | 7 | 没有 | 存 `2 → 0`，本子 `{2→0}` |
| 1 | 7 | 2 | **有！（下标 0）** | 返回 `[0, 1]` ✅ |

再看一个（体现「先查后存」）：`nums = [3,3], target = 6`

| 下标 | `x` | 补数 `6 - x` | 本子里有吗？ | 动作 |
|---|---|---|---|---|
| 0 | 3 | 3 | 没有 | 存 `3 → 0` |
| 1 | 3 | 3 | **有！（下标 0）** | 返回 `[0, 1]` ✅ |

### 7. 你要做的

用**带下标的循环**遍历（因为要返回下标！复习 `for (let i = 0; i < nums.length; i++)`），
对每个 `nums[i]` 求补数 `target - nums[i]`，用 `Map` 的 `has` / `get` 查、`set` 存。
（`Map` 的三个动作见《零基础精讲 ②》。）

**题目**：给定整数数组 `nums` 和整数目标值 `target`，请你在该数组中找出**和为目标值 `target`** 的那**两个**整数，并返回它们的**数组下标**（保证恰好一个答案；同一元素不能重复使用；返回顺序任意）。

- 示例：`nums = [2,7,11,15], target = 9 -> [0,1]`（因为 2 + 7 = 9）
- 示例：`nums = [3,2,4], target = 6 -> [1,2]`
- 示例：`nums = [3,3], target = 6 -> [0,1]`
- 约束：`2 ≤ nums.length ≤ 10^4`

**🧪 本地验证指令**（在仓库根目录执行）：
```bash

npx tsc --noEmit                                        # 严格类型检查
```

**✍️ 我的思路**（先自己写，哪怕一句话）：
>对每一个数字，我们关心的是他的补数在不在map中存过了

**✍️ 我的代码（TypeScript）**：

> （Agent 按 R8 整理，仅调整空格，未改结论）

```ts
export function twoSum(nums: number[], target: number): number[] {
  const num_map = new Map<number, number>();
  for (let i = 0; i < nums.length; i++) {
    if (num_map.has(target - nums[i])) {
      return [i, num_map.get(target - nums[i]) ?? 0];
    }
    num_map.set(nums[i], i);
  }
  return [-1, -1];
}
```

**复杂度自评**：（未填）→ 正确：**时间 O(n) ｜ 空间 O(n)**

**✅ 批改（2026-09-27）**：

**判定**：✅ **AC** —— `vitest` **4/4 全绿**，`npx tsc --noEmit` **无错误**。
思路一句话说到点子上（「关心补数在不在 map 里」），实现也是标准的「先查后存」。

**值得肯定**：
- 先 `has` 再 `set` —— 正确避开「自己和自己配对」的坑；
- 返回 `[i, 补数下标]`，用 `?? 0` 兜住 `get` 的 `undefined`（类型上安全）；
- `for (let i = 0; ...)` 用了下标，符合「要返回下标」的需求。

**3 根小刺（不影响 AC）**：
1. 命名风格：`num_map` 是下划线命名（snake_case），TS 习惯用**小驼峰**（camelCase），建议 `numMap` 或更贴切的 `seen`。
2. `?? 0` 其实可以省：上一行已 `has(...)` 确认存在，`get` 一定拿得到值。保留也无害（更保险），但要知道它「此处非必需」。
3. 空格：`new Map<number,number> ()` → `new Map<number, number>()`；`i < nums.length ;` → `i < nums.length;`。

**复杂度复核**：**时间 O(n)**（一次遍历，每个元素 O(1) 查 + O(1) 存）｜ **空间 O(n)**（最坏存下所有元素）。你的自评是空的，记得写。

**复盘**：
- 卡点：无（一次通过）。
- 从暴力到最优的演进：两层循环 O(n²) → 用 Map 把「找补数」降到 O(1)，整体 O(n)。
- 一句话套路：**遍历时对每个 `x` 查「`target − x` 见过没」；先查、后存。**

**📘 C++ 对照（TS 通过后阅读）**：

```cpp
// cpp/01-hash-table/0001-two-sum.cpp
#include <vector>
#include <unordered_map>

std::vector<int> twoSum(const std::vector<int>& nums, int target) {
    std::unordered_map<int, int> seen;      // 数 -> 下标
    for (int i = 0; i < (int)nums.size(); i++) {
        int need = target - nums[i];        // 补数
        auto it = seen.find(need);          // find 返回"迭代器"
        if (it != seen.end()) {             // 找到（没到末尾）
            return {it->second, i};         // {补数下标, 当前下标}
        }
        seen[nums[i]] = i;                  // 先查后存
    }
    return {};
}
```

- **TS ↔ C++ 关键差异**：

  | 目的 | TypeScript | C++ |
  |---|---|---|
  | 返回多值 | `return [a, b]`（数组） | `return {a, b};`（`std::vector<int>` 初始化列表） |
  | 查键 | `m.has(k)` / `m.get(k)!` | `auto it = m.find(k); it != m.end(); it->second` |
  | 写键 | `m.set(k, v)` | `m[k] = v` |
  | 长度 | `nums.length` | `(int)nums.size()`（`size()` 返回无符号，比较时习惯转 `int`） |
  | 下标循环 | `for (let i = 0; ...)` | `for (int i = 0; ...)` |

## 零基础精讲 ④：把「同一类」的归到一起——归一化 key（真题 49 配套）

> 目标：先搞懂「怎么判断两个单词是同一类」，再谈写代码。

### 1. 题目在问什么

给一堆字符串，把**互为字母异位词**的分到同一组。

- **字母异位词（anagram）**：字母的**种类和个数完全相同**，只是**顺序不同**。
  - 例：`eat`、`tea`、`ate` 是异位词（都恰好是一个 a、一个 e、一个 t）。
  - `eat` 和 `bat` 不是（字母不一样）。
- 例：`["eat","tea","tan","ate","nat","bat"]` →
  `[["eat","tea","ate"], ["tan","nat"], ["bat"]]`（组内、组间顺序都不限）。

### 2. 核心难点：怎么判断「两个词是同一类」？

一个个两两比较太慢。换个角度：**同一类的词，有没有一个共同的「标准形」？**

把每个词**按字母排序**看看：

| 原词 | 排序后 |
|---|---|
| eat | `aet` |
| tea | `aet` |
| ate | `aet` |
| tan | `ant` |
| nat | `ant` |
| bat | `abt` |

**同一类的词，排序后完全相同！** 这个排序后的字符串就叫这一类的**归一化 key（canonical key）**。

> 类比：按「身份证号」给每个人分房间——不管名字怎么写，号码一样就是同一类。

### 3. 用小本本把同类装到一起

用 `Map`：

- **键（key）** = 归一化后的字符串（如 `"aet"`）；
- **值（value）** = 这一类目前的单词列表（如 `["eat","tea","ate"]`）。

遍历每个单词 `s`：

1. 算出 `s` 的 key（字母排序）；
2. 看小本本里有没有这个 key：没有就先开一个空列表放进去，有就取出这个列表；
3. 把 `s` 追加进列表；
4. 最后把小本本的**所有值**（各组列表）收集起来返回。

### 4. 新语法：字符串「切开 → 排序 → 拼回」

```ts
const key = s.split("").sort().join("");
```

- `s.split("")`：按每个字符切开：`"eat"` → `["e","a","t"]`；
- `.sort()`：排序：`["e","a","t"]` → `["a","e","t"]`；
- `.join("")`：拼回字符串：`["a","e","t"]` → `"aet"`。
- 连读：**切开 → 排好 → 拼回**，得到「标准形」。
- （已登记到 `notes/typescript-basics.md` 第 **013** 条。）

### 5. 「取不到就新建」的小套路

要保证「key 对应的列表」存在后再放单词，常见写法：

```ts
const list = map.get(key) ?? [];  // 有就取出；没有就先用一个空数组
list.push(s);                     // 把当前单词加进去
map.set(key, list);               // 写回小本本
```

- `map.get(key) ?? []`：取得到就用它，取不到（还没建）就用一个新的空数组。

### 6. 跟着走一遍（前 4 个词）

| 单词 `s` | `key`（排序后） | 小本本（key → 列表） |
|---|---|---|
| eat | `aet` | `{aet: [eat]}` |
| tea | `aet` | `{aet: [eat, tea]}` |
| tan | `ant` | `{aet: [eat, tea], ant: [tan]}` |
| ate | `aet` | `{aet: [eat, tea, ate], ant: [tan]}` |

### 7. 复杂度（先有感觉，批改时复核）

- 有 `n` 个单词，平均每个长 `k`；
- 每个单词排序一次：`O(k log k)`；
- 总共 **时间 O(n · k log k)** ｜ **空间 O(n · k)**。

### 8. 你要做的

用 `for (const s of strs)` 遍历，对每个 `s` 算出 key，按第 3、5 步塞进 `Map`，
最后用 `[...map.values()]` 返回所有分组。（`...` 与 `map.values()` 见精讲第 8 步引用的 **014** 条。）
