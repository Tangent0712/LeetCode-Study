## 套路卡（进入专题先读这张卡）

- **什么时候用**：需要快速判断「某元素是否出现过 / 出现几次 / 和某个值配成一对 / 归类」。
- **核心思想**：建立 `key -> value` 的映射（Map/Set），把线性查找换成常数级查找。牺牲空间 O(n)，换时间从 O(n²) → O(n)。
- **TypeScript 模板**：
  ```ts
  // 配对型：先查后存
  const seen = new Map<number, number>(); // key: 值, value: 下标
  for (let i = 0; i < nums.length; i++) {
    const need = target - nums[i];
    if (seen.has(need)) return [seen.get(need)!, i];
    seen.set(nums[i], i);
  }
  ```
- **复杂度特征**：时间 O(n)（均摊）/ 空间 O(n)
- **常见坑**：
  - 「先查后存」——否则元素会和自己配对；
  - TS 里 `Map` 与普通对象 `{}` 的键类型差异（对象键会被转成字符串）；
  - 字符计数用**定长数组**（`new Array(26)`）比 Map 更快；
  - `Map.get` 返回 `T | undefined`，注意 `!` 或判空。
- **术语**：hash table 哈希表 / hash function 哈希函数 / collision 冲突 / bucket 桶 / count 计数 / frequency 频次 / anagram 字母异位词。

### 为什么哈希是 O(1)？（底层一览）

```
   key ──hash()──► 桶编号 (bucket index)
 "apple" ────────►  #3
 "banana" ───────►  #7
 "cherry" ───────►  #3   ← 和 apple 撞桶了（哈希冲突）

 查询 "banana"：算出 7 → 直接跳到 7 号桶 → 取出来。平均 O(1)
```

- **哈希函数（hash function）** 把任意 key 映射成桶下标；查询时同样算一次即可定位。
- 不同 key 可能落到同一桶 → **哈希冲突（collision）**；用**链地址法**（桶是链表）或**开放寻址**解决。
- 冲突太多时性能退化，所以严格说是「**平均** O(1)、最坏 O(n)」。
- 类比：哈希表像**图书馆按首字母分区**——你不需要翻遍所有书，先看首字母就知道去哪个书架。
